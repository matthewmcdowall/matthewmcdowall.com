# matthewmcdowall.com

Visual system ("ICARUS REBORN" restyle, developed in a local copy at `~/projects/site-copy` and promoted to this repo in Oct 2026; the previous design is tagged `pre-icarus-restyle`): re-sculpted after the @icarus.reborn TikTok aesthetic: paper white / oxblood red / black, thin Inter type, text that types itself out with a blinking cursor (`data-type`), a translucent pyramid as the mark (`components/Pyramid.tsx`: nav logo, contact card, footer, and the OG image), with a tiny solid triangle (`.tri` / the `::before` prefixes, and `tri()` in the HUD) standing in for it on chips, labels and crosshairs — the user rejected the earlier cross and the `+` glyphs, and red machine-vision "tracker" overlays (`.tracker` containers get boxes, coordinate labels and a dashed path from `ClientBehaviors.tsx`). Cards use hairline borders with red viewfinder corners; no shadows or radii anywhere. `components/Ambient.tsx` (mounted in `app/layout.tsx`) decodes `public/video/koi.mp4` (Wikimedia Commons, "Koi pond in Otaguro Park" by Dandy1022, CC BY-SA 4.0 — trimmed, ping-pong looped and posterized; the credit in the footer is a licence requirement, keep it) into a small buffer each frame, posterizes it to paper/ink/red, finds ink/red blobs on a coarse grid and tracks them so the HUD boxes follow real fish; a generative koi-and-birds scene is the fallback when the video can't play. Tracking: `findBlobs` runs red and ink cells as separate classes (a red koi beside a dark one gets its own box) and drops blobs wider than ~45% of the frame; boxes ease at 0.24. No spiral, no lock→target connectors (the user found them cluttering); trails are short and solid. A standing corruption (`err_00`) is anchored to `[data-corrupt-anchor]` — an absolutely-positioned box top-right of the Experience section, above the heading — so it scrolls with the page and only shows there; flips between block and strip forms every 2–4.5 s, hidden in quiet mode. `.viewfinder` elements are looks into the real pond — they show the raw full-colour video frame, not the posterized print (which only flashes through at a burst) — currently only the About feed. The small scattered ones were removed on request (the user found them random); `.vf-sm`/`.vf-md`/`.vf-abs` styles remain so windows can be placed exactly where the user asks: `<div className="viewfinder vf-sm" data-label="feed_NN — word" aria-hidden />`. It composites the scene, composites it on a fixed canvas behind the page at 0.3 alpha (0.14 was so faint the posterized blocks read as a blur rather than as a print) and sharply inside `.viewfinder` elements on a fixed canvas above it, and runs the HUD there: boxes/trails/coordinates tracking the subjects, bracket locks on real elements (chips, tags, stats), dashed connectors, a scanline, a readout, periodic datamosh bursts, and slice glitches on `[data-glitch]` text. Subjects are pulled toward visible viewfinders so the feed windows are never empty. Pacing (user asked for calmer): koi video at 0.6× speed, box easing 0.12, **one** tracker box, the largest (two competing boxes read as clutter; the biggest is the one actually sitting on a fish) + 2 locks on desktop (1 lock on phones), locks every 4.5–8 s, bursts every 14–24 s, text glitches every 10–18 s. Corruptions: every 12–20 s (and with half the bursts), one at a time a tear — jagged rip, sheared strips or pixel blocks — opens somewhere (half the time riding a tracked fish), reveals the *raw full-colour* koi frame through it, flickers and mutates for 0.7–1.9 s, then snaps shut; none in quiet mode. Performance invariants (enforced by `e2e/perf-*.spec.ts`, so read them before touching the render loop): the canvases render at 1x (backdrop) / ≤1.25x (HUD) with `imageSmoothingEnabled = false` — the print comes from a 480x270 buffer, so more device pixels cost a full-screen blit and buy nothing; each clip is decoded **once per video frame** into a `raw` canvas and everything else blits from that (drawing from a `<video>` element converts the whole frame every time); feed windows and tears draw only their own slice via `drawCoverRect`/`drawSceneRect`, because clipping a full-screen `drawImage` still pays for the whole blit; the backdrop is only rebuilt when the clip actually advances or a burst is running; and a one-way quality guard drops the backdrop to 0.5x then 0.35x after a run of sub-24fps frames (exposed as `window.__ambientQuality`). **The HUD keeps off the copy.** Effects are faded per element by what is underneath them rather than masked per pixel: `collectReadRects()` measures content blocks (`READ_TARGETS`) in *document* space so the per-frame test is arithmetic with no layout reads, `updateFocus()` eases a 0-1 focus value per block (1 while the pointer is on it, or while it sits in the middle `H * 0.36` reading band), and `fadeOver(x, y, w, h, base, scrollY)` returns how far an effect there must dim. Coverage **accumulates** across blocks rather than taking the worst single one — an effect straddling two paragraphs is over content twice, and a `<p>` inside a `.card` double-counts on purpose. `base` is `CONTENT_FADE` (0.78) for tracker boxes, trails and corruptions, so they never sit on text at full strength and vanish entirely over what is being read; locks and scribbles pass `0` because they are aimed at page elements deliberately and should only retreat when that element is in focus. `READ_TARGETS` lists both `#siteContent` and `main` roots — the homepage has no `<main>`, and an earlier `main p` selector silently matched nothing, leaving all the body copy unprotected. Measured at a card's centre the fade is 0.00 and in the gutter beside it 1.00, so the HUD lives in the margins. `window.__fadeAt(x, y, w, h)` is a dev hook that reports the value, alongside `window.__corrupt`. **About stands the HUD down entirely.** `<section id="about">` carries `data-ambient="calm"`, and the ambient layer goes quiet while any such element covers more than 18% of the viewport — About runs from its heading through the tech marquees, and floating blocks drifting over that much copy read as noise. `calm` differs from `quiet` only in being scoped to visibility rather than to the whole page. The About feed window keeps drawing, because feed windows are painted before the `hudAlpha` gate. Covered by `e2e/ambient.spec.ts`, which samples the HUD readout strip along the bottom (it fades with `hudAlpha` and no feed window draws there) at the hero, About, the marquees and Experience. **The backdrop survives the clip dying.** `processVideo()` returns null whenever `video.currentTime` has not advanced, which is normal between decoded frames — but if the clip stops for good (a dropped connection, a dev server restarting under an open tab, a hard throttle) it returns null every frame, `sceneDirty` is never set and the backdrop freezes for the life of the page with no way back. A `lastAdvance` timestamp now guards it: after 1.5s stalled it retries `play()`, and after 5s it clears `videoOk` so the generative koi scene takes over, flipping back to the clip if it ever resumes. Covered by `e2e/ambient.spec.ts`. Quiet mode: while a `[data-ambient="quiet"]` element exists (the contact page's `<main>`) or the footer is in the viewport, the HUD fades out and bursts/locks/glitches stop, leaving only the koi backdrop (and any feed windows). **There is no opening animation.** The homepage loads straight into the page — no overlay, no gate on `#siteContent`, and `ClientBehaviors.tsx` starts the hero sequence on mount rather than waiting for a handover. Three successive openings were built and then scrapped on request: a growing oak, a fully CG volcano, and finally real Etna eruption footage with a Blender ash pass and a canvas lightning strike over it. All of it is gone — `components/Intro.tsx`, the `.terminal-overlay`/`.intro-*` CSS, the `.site-content` opacity gate, `scripts/blender/`, and every clip but `koi.mp4`. The Etna footer credit went with the footage, since the licence only obliges a credit while the work is being distributed; the koi credit stays because `Ambient.tsx` still ships that clip. `e2e/hero.spec.ts` replaces the old `intro.spec.ts` and asserts there is no overlay; `waitForPage` in `e2e/helpers.ts` replaces `waitForIntro`/`INTRO_MS` and waits on the ambient canvas as proof that client JS is live. If an opening is ever wanted again, the retired pieces were never committed — the restyle was built outside git, so they are not recoverable from history. The hero's "let's talk" button is generated on screen (its code types out, slice-glitches, then the button animates in with lock brackets) on the same tick as "Got an idea?" starts typing. No photos of the user: the About photo and the Prime Ready group photo were removed and became feed windows; the OG image is the generated `public/og.png` sigil card. Legacy variables `--cyan`/`--yellow` are aliased to the new palette so old inline styles still resolve.

## Structure
- `app/page.tsx` — the entire homepage in one file ( nav → hero → about/bento-stats/tech marquee (the Skills section was merged into About, no heading) → experience (products embedded under North Light AI; SubCom, SBDC, Cohasset) → education → blog (skeleton: up to 3 real posts from `content/blog`, dashed placeholder cards with breathing bars after, link to /blog) → contact — the Projects section was removed on request). Content is hardcoded JSX, not CMS-driven.
- `app/blog/`, `content/blog/*.md` — blog index + `[slug]` pages, posts are markdown with frontmatter, rendered via `next-mdx-remote/rsc`. `lib/content.ts` reads them (`draft: true` in frontmatter excludes a post).
- `app/contact/page.tsx`, `app/api/contact/route.ts`, `components/ContactForm.tsx` — contact form flow, the site's only dynamic write surface. The route checks `Origin` against the served host (blocks cross-site POSTs without a hardcoded domain list, so previews and localhost work), caps the body at 16 KB, rate-limits per IP (in-memory, bounded; uses Netlify's `x-nf-client-connection-ip`), has a honeypot, validates with zod (`name` rejects line breaks), escapes HTML for the email body, and sends via Resend. Env is read through `lib/env.ts` (`server-only`, parsed lazily).
- `next.config.ts` — security headers incl. a CSP. Scripts use `'unsafe-inline'` on purpose: nonces would force per-request rendering and kill ISR. If you add a third-party script, frame, or fetch target, add its host to the matching directive there.
- `lib/content.ts` — blog slugs are whitelisted to `[a-z0-9-]` and `app/blog/[slug]` sets `dynamicParams = false`, so only pre-generated posts resolve. MDX is compiled from `content/`, i.e. blog content is code — only commit posts you'd run.
- `lib/data.ts` — homepage bento-grid stats. GitHub + Hugging Face are unauthenticated public-API `fetch` calls with `next.revalidate: 3600`, and `app/page.tsx` exports `revalidate = 3600`, so the homepage is ISR — **don't add `cache: 'no-store'`, `cookies()`, `headers()` etc. to the homepage render path**, it silently flips the route to per-request rendering (an earlier Strava integration did exactly that; Strava was removed in Sep 2026 after Strava deactivated the API app). Claude stats come from the bundled `public/data.json` (static import, not `fs`), which is also the fallback for the two live fetches.
- `public/data.json` — committed, durable record of Claude Code usage. `scripts/sync-claude-stats.py` (`pnpm sync-stats`) merges `~/.claude/stats-cache.json` (the same numbers `/usage` shows), `history.jsonl`, and the session transcripts into the `claude` key — field-wise max per day, never dropping a day, because Claude Code prunes its transcripts after ~30 days and the cache is a rolling window too. It writes nothing if unchanged. `scripts/sync-and-push.sh` wraps it for launchd (`scripts/com.matthewmcdowall.portfolio-stats.plist`: 06:00 daily + 12:00 retry, 20h throttle, commits only that path, refuses to run off `main`); the push is what triggers the Netlify deploy. Only aggregate counts are written — no prompts or paths.
- `scripts/` — Python needs only the stdlib; the shell script sets its own `PATH` because launchd's is minimal.
- `components/ClientBehaviors.tsx`, `components/BentoData.tsx` — client-side DOM manipulation (`useEffect` + `document.getElementById`) for scroll-reveal, nav highlighting, the typed hero sequence + generated CTA, and populating the bento stats/heatmap. This is intentionally imperative (ported from the original static HTML/JS site), not idiomatic React state — match that style when touching these files rather than converting to React state.
- `lib/site.ts` — SEO identity: site URL, `<title>`, meta description, OG image, social URLs, and the schema.org Person/WebSite JSON-LD. `app/layout.tsx` builds its metadata from it (OG/Twitter deliberately omit title/description so each page inherits its own), `app/page.tsx` injects the JSON-LD and sets the canonical, and `app/robots.ts` / `app/sitemap.ts` generate `/robots.txt` and `/sitemap.xml`. The title/description are written for recruiter boolean searches (name first, then role and stack keywords) — edit the copy there, not in the layout.
- `app/globals.css` — single ~1200-line stylesheet for the whole site (not Tailwind utility classes for most of the UI, despite Tailwind being a dependency).

## Env vars
`lib/env.ts` is the source of truth and matches `.env.local.example`: `RESEND_API_KEY`, `CONTACT_TO`, optional `RESEND_FROM` (contact form). No other feature needs a secret; the live-stat APIs are public.
